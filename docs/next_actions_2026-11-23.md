# 밤 작업 뒤 남은 일 (2026-11-23 09:10 정리)

밤 작업 보고(`docs/night_report_2026-11-23.md`)와 사실 확인표(`docs/resume_fact_check.md`)를 읽고 정리했다. 밤 작업은 7개 항목이 모두 끝났고, 커밋·푸시·운영 테이블 쓰기는 없었다.

## 1. 밤사이 알게 된 것 (세 줄)

1. **DuckDB 메모리 원인이 좁혀졌다.** 디스크로 내린 데이터를 가리키는 장부(`ALLOCATOR`)가 내린 양에 비례해 쌓인다(1GiB당 0.06~0.11GiB). 문자열 키를 고정 길이 키로 바꾸면 약 1/5로 준다. 새 프로세스는 필수가 아니었고, 누적 결과를 파일로 넘기면 한 프로세스에서도 14억 행이 끝난다(측정 60~63).
2. **Spark가 느린 이유가 나왔다.** 같은 집계를 원본부터 세 번 계산하고, 거의 줄지 않는 부분 집계(0.05%)가 단계마다 300GB 넘게 디스크로 내린다. 시간의 89~95%가 CPU다(측정 64).
3. **이력서 수치 16개 중 1개가 틀렸고 9개는 조건이 빠졌다.** 특히 "5개 파일 → SQL 2줄"은 실제 변경이 아니라 흉내 낸 변경이고, 28 → 1은 대표값이 아니라 많이 줄어든 쪽이다(중앙값은 41 → 11).
