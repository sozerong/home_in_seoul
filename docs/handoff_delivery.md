### P3. 버전 간 변경 기록과 변경 정책

- 문제: 버전 기록 탭에는 행 수, 용량, sha256만 있다. 다음 버전에서 컬럼이 빠지거나 뜻이 바뀌어도 분석가가 알 방법이 없다. 〔근거: warehouse/site/index.html tabVersions〕
- 이미 있는 것: 〔근거: README 5절, docs/guarantees.md〕
  - manifest.json(버전별 파일, 행 수, sha256, 출처 기준일, 품질 지표)
  - public_columns.json(컬럼 사전)
  - 같은 버전 이름으로 다른 내용을 올리면 실패하는 검사(check_versions)
  - 파이프라인 안의 같음 증명(두 방향 EXCEPT ALL, 상품 sha256)
- 할 일: 〔근거: 판단〕
  1. `publish_site.py`가 새 버전을 만들 때 직전 공개 버전과 비교한 결과를 catalog에 싣는다. 항목은 추가된 컬럼, 빠진 컬럼, 형 변경, 행 수 변화, 품질 지표 변화, 출처 기준일 변화다.
  2. 빠진 컬럼이나 형 변경이 있는데 `public_columns.json`에 의도 표시(`removed` 또는 `changed`, 사유 포함)가 없으면 실패한다.
  3. `docs/data_contract.md`에 1절 변경 정책 3줄을 적는다.
  4. 버전 기록 탭에 변경 표를 보인다.
- 끝난 기준: 컬럼 하나를 뺀 두 표본 버전으로, 표시가 없으면 실패하고 표시가 있으면 변경 표에 나타나는 selftest가 하나 있다(`selftest_site`에 추가). `docs/guarantees.md`에 강도(매 실행 강제)를 적는다. 〔근거: CLAUDE.md 8절(성질 시험은 guarantees.md)〕
