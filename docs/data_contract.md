# 데이터 계약: 서울 행정동 주거 지표 (부동산 플랫폼용)

상태: **초안 (2026-10-22).**

받는 쪽: 부동산 플랫폼의 "동네 정보" 기능(결정 12). 이 데이터는 직장, 예산, 출퇴근 한도를 **입력받지 않는다.** 행정동마다 미리 계산한 값을 주고, 거르고 정렬하는 일은 받는 쪽이 한다. 사용 예는 `warehouse/sql/demo.sql`.

## 1. 배포
| 항목 | 내용 |
|---|---|
| 위치 | `product/vYYYY.MM.DD/` (버전 = 내보낸 날짜) |
| 파일 | `dong_profile`, `commute_od`, `rent_listing`, `dong_mois_map` 각각 `.parquet`(형식 보존)과 `.csv`(UTF-8 BOM, 엑셀용). 경계 도형은 주지 않는다(결정 26). `manifest.json` |
| manifest | 버전, 만든 시각, 파일마다 행 수와 sha256, 원천 데이터의 기준(수집일, 기준월), 품질 지표 |
| 갱신 주기 | 주 1회 권장(전월세, 혼잡도, 역은 매주 월요일 수집). 출퇴근은 월 1회(생활이동 매월 21일 이후), 편의는 분기, 경계는 연 1회 |
| 같은 버전 다시 만들기 | 같은 날 다시 내보내면 그 버전 폴더를 새로 만든다. 같은 입력이면 같은 내용이다 |

## 2. 공통 규칙
- **행정동 기준은 2025년 통계청 SGIS 경계**(기준일 2025-06-30, 서울 426개). 키는 `dong_id`(통계청 8자리). 행정안전부 행정동 코드 `mois_dong_cd`(8자리)를 함께 준다(결정 13).
- 금액 단위는 **만원**(`*_10k_won`), 면적은 ㎡, 거리는 m, 시간은 분.
- 좌표와 도형은 주지 않는다. 거리·면적은 내부에서 EPSG:5179(미터)로 계산한 숫자로 준다. 지도에 그리려면 받는 쪽이 이용조건이 맞는 경계를 따로 쓴다(결정 26).

## 3. 파일별 스키마

### dong_profile (한 행 = 행정동 하나, 426행)
| 컬럼 | 뜻 |
|---|---|
| dong_id, mois_dong_cd, dong_nm, sgg_cd | 행정동 코드(통계청), 행정안전부 코드, 이름, 통계청 시군구 코드 |
| area_km2, boundary_base_date | 면적(㎢), 경계 기준일 |
| monthly_deals, monthly_median_deposit_10k_won, monthly_median_rent_10k_won | 최근 6개월 신규 **월세** 계약 수와 보증금·월세 중앙값 (면적 조건 없음) |
| jeonse_deals, jeonse_median_deposit_10k_won | 최근 6개월 신규 **전세** 계약 수와 보증금 중앙값 |
| nearest_station_nm, nearest_station_route, nearest_station_distance_m | 행정동 안 대표점에서 가장 가까운 역(모든 노선) |
| nearest_congestion_station_*, am_peak_congestion | 혼잡도 자료가 있는(1~8호선) 가장 가까운 역과, 그 역의 **평일 07:00~09:00 최대 혼잡도**(%, 좌석 수만큼 타면 34) |
| convenience_store, supermarket, pharmacy, internal_pediatric_clinic, laundry | 필수 5종 업소 수(세탁 = 세탁소 + 셀프 빨래방) |
| *_per_km2 | 위 업소 수 ÷ 면적 |

### rent_listing (한 행 = 최근 6개월 신규 전월세 계약 한 건)
지금은 25개 구 × 2개 출처가 모두 들어온 계약월이 4개(202606~202609)뿐이라 4개월치다. 매주 수집과 백필로 6개월이 찰 때까지 manifest의 `rent_months`가 실제 기간이다.
| 컬럼 | 뜻 |
|---|---|
| dong_id, mois_dong_cd, dong_nm | 거래 필지가 속한 행정동 |
| source_type, house_type | offi(오피스텔) / rh(연립다세대), 연립다세대의 주택 유형 |
| lease_type | 월세(월세 > 0) / 전세(월세 = 0) |
| deal_ymd, deal_date | 계약년월, 계약일 |
| deposit_10k_won, monthly_rent_10k_won, excl_area_m2, floor, build_year | 보증금, 월세, 전용면적, 층(지하는 음수), 건축년도 |

### commute_od (한 행 = 출발 행정동 × 직장 행정동)
| 컬럼 | 뜻 |
|---|---|
| origin_dong_id, dest_dong_id | 출발(야간상주지), 직장(주간상주지) 행정동 |
| avg_minutes_age20_34, population_age20_34 | 20~34세의 이동인구 가중 평균 이동 시간, 가려지지 않은 이동인구 합 |
| avg_minutes_all_ages, population_all_ages | 전체 나이 |
| avg_minutes, basis | 권장 값. 20~34세 이동인구 합이 30 이상이면 20~34세, 아니면 전체 나이. 30 미만에서는 두 평균의 차이가 크게 흔들려서 정한 기준(결정 22) |
| copied_from_2021_split_dong | 2021년 이후 나뉜 동(상일1·2동, 오류2동·항동)에 2021년 값을 복사한 행 |
| distance_km | 두 행정동 안 대표점 사이 직선거리(km). 이동 시간이 근거리에서 길게 나오는 약점을 보완한다(결정 23). 권장 사용: 이동 시간 한도 이하 **또는** 3km 이내 |
| target_months | 원천 대상연월. 생활이동이 있는 최근 6개 대상연월 안에서 이 경로가 나온 달 (결정 36) |

### dong_mois_map (한 행 = 행정안전부 행정동 코드 하나, 427행)
| 컬럼 | 뜻 |
|---|---|
| mois_dong_cd | 행정안전부 행정동 코드 8자리 (키) |
| dong_id, dong_nm | 그 코드가 속한 통계청 2025 행정동 |
| is_primary | 그 행정동의 대표 코드인가 (dong_profile.mois_dong_cd와 같음) |
| stores, share | 근거: 그 행정동 경계 안 필수 5종 업소 중 이 코드를 가진 업소 수와 비율 |

행정안전부 코드로 잇는 플랫폼은 `dong_profile.mois_dong_cd` 대신 이 표로 잇는다. 426개 동 중 425개는 코드 하나와 1:1이고, **용신동만 둘**이다(11230515 신설동 53.6%, 11230533 용두동 46.4%. 이름은 상가정보의 행정동명). 통계청 2025 경계의 용신동 하나가 행정안전부 코드로는 두 동에 걸친다(결정 25).

## 6. 알려진 한계
1. **출퇴근 시간의 뜻**: 생활이동의 평균 이동 시간은 "매우 가까운 근거리 이동 제외", "짧은 경유는 이동에 포함"으로 만들어져(매뉴얼 1.7, 2.2), 가까운 동네일수록 실제보다 길게 나온다(예: 역삼1동 → 역삼1동 148.7분). 대중교통 출퇴근 시간이 아니고 수단 구분도 없다. 그래서 직선거리(distance_km)를 함께 주고, 이동 시간 한도 **또는** 3km 이내를 권장한다(결정 23). 대중교통 길찾기 시간은 다음 버전 과제다.
2. **다가구 원룸이 빠진다**: 단독·다가구 전월세는 지번이 없어 넣지 않았다(question.md 2절).
3. **혼잡도는 최신 분기가 아니다**: API가 20251130 분기 파일과 같은 값을 준다(결정 7). 경로 전체가 아니라 집 근처 역 한 곳의 값이고, 방향은 두 방향 중 큰 값이다.
4. **이동인구 3명 이하는 가려져 있다**: 가중 평균에서 빠진다. 20~34세는 경로의 14%가 모두 가려져 전체 나이로 대체된다.
5. **신고 지연**: 최근 달의 전월세는 신고가 덜 들어온 상태다. 다시 받을 개월 수는 측정 중(측정 1).
6. **행정안전부 코드 대응은 데이터로 만든 것**이다(공식 대응표와 대조하지 않았다).
