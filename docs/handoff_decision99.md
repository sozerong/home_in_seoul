# 작업 지시: 남은 구현 먼저, 오류 처방은 그다음 (결정 99, 2026-11-13)

Claude Code가 이 문서와 `docs/decisions.md` 결정 99를 읽고 위에서부터 진행한다. CLAUDE.md, `docs/design_remaining_work.md` 0절의 규칙은 그대로다.

## 규칙

- 남은 구현을 먼저 끝내고 오류 처방은 그다음에 한다.
- 오류는 지금처럼 `docs/failure_analysis.md`에 원인까지 기록만 한다.
- 오류가 남은 구현을 막거나 같은 일일 때(연관 있음)만 가장 작은 처방을 먼저 하고 F 항목에 적는다.
- 성질(멱등, 동등 등)을 시험하면 `docs/guarantees.md`에 방법, 근거, 조건, 강도, 한계를 남긴다(결정 98).

## 순서

1. **커밋.** 지금까지 작업(3절, F-5·F-6·F-7 처방, F-16 기록, `guarantees.md`, 결정 96~99)을 커밋한다. 절 단위로 나눠도 된다.
2. **생활이동 관문 판정과 격리 행을 PostgreSQL에 남긴다(판단 64).** 다른 세 출처처럼 운영 카드와 알림 요약에 생활이동 거절이 보여야 한다.
3. **생활이동 "거절되면 직전 승인 배치"(판단 63)는 설계 문제다.** 선택지를 표로 보이고 멈춘다. 지금 구조에 이미 있는 것(예: Iceberg 스냅샷)도 짚는다. 사용자가 고른다.
4. **8절 옛 경로 은퇴.** 지울 목록을 먼저 보이고 확인받은 뒤 지운다. 지우기 직전 커밋에 태그 `pre-retire-python`.
5. **3.9 DuckDB 비교.** F-16과 연관 있으므로 먼저 이것만 한다.
   - DuckDB에 `threads` 12, `memory_limit`, `max_temp_directory_size`를 명시한다. 값은 그 시각 호스트 C: 여유를 기준으로 계산해 근거와 함께 적는다.
   - 측정 도구는 `python -u`로 돌린다(출력 버퍼 없음).
   - 사용자가 가상 디스크 공간 회수(diskpart compact)를 했는지 먼저 묻는다. 안 했으면 상한이 작아 DuckDB가 오류로 끝날 수 있다. 그것도 F-16 처방 확인(멈추지 않고 오류로 끝나는가)으로 기록한다.
   - 한 번에 하나만 돌린다.
6. **체크포인트로 보고하고 멈춘다.**
